# Архитектура проекта Tendrix (FZ Parser)

Проект представляет собой систему автоматизированного сбора, анализа и уведомления о государственных и коммерческих закупках (тендерах) с использованием технологий ИИ.

## Обзор системы

Система состоит из трех основных частей:
1.  **Backend (FastAPI)**: Центральный узел, управляющий данными, аутентификацией и интеграцией с ИИ.
2.  **Парсеры (Scrapers)**: Набор модулей для сбора данных из различных источников в режиме 24/7.
3.  **Frontend (React + Vite)**: Пользовательский интерфейс для поиска, фильтрации и анализа тендеров.
4.  **Telegram Bot (Aiogram)**: Сервис для привязки аккаунтов и получения мгновенных уведомлений.

---

## Технологический стек

-   **Backend**: Python 3.10+, FastAPI, SQLAlchemy, Pydantic.
-   **Database**: SQLite (sql_app.db) — используется для хранения пользователей, тендеров и настроек.
-   **Frontend**: TypeScript, React, Vite, Tailwind CSS (в `temp_frontend`).
-   **AI Integration**: OpenAI API (GPT-4o) для извлечения ключевых слов, оценки релевантности и анализа рисков (pitfalls).
-   **Scraping**: BeautifulSoup4, Requests, Httpx.
-   **Bot**: Aiogram 3.

---

## Структура файлов

### Ядро и API
-   `main.py`: Точка входа API, определение эндпоинтов, логика фоновых потоков синхронизации.
-   `database.py`: Определение моделей данных (User, Tender, PromoCode) и инициализация БД.
-   `auth.py`: Логика аутентификации (JWT, хеширование паролей).

### Сбор данных (Парсеры)
Система использует многопоточный подход для агрегации данных:
-   `zakupki_parser.py`: Основной парсер для ЕИС (zakupki.gov.ru). Работает через HTML-скрапинг.
-   `sberbank_ast_parser.py`: Парсер для площадки Сбербанк-АСТ (использует ElasticSearch API).
-   `external_parsers.py`: Универсальный парсер для внешних источников (на основе sitemaps и robots.txt). Конфигурируется через `external_sources.json`.
-   Специализированные парсеры площадок: `roseltorg_parser.py`, `tektorg_parser.py`, `etp_ets_parser.py` и др.

### Уведомления и Боты
-   `bot.py`: Telegram бот для связки аккаунта пользователя с его профилем в системе.
-   `tg_notify.py`: Модуль рассылки уведомлений о новых релевантных тендерах.

## Архитектура данных (Модели)

### Tender (Тендеры)
Хранит информацию о закупке:
-   `number`: Реестровый номер.
-   `subject`: Предмет закупки.
-   `price` / `currency`: Стоимость и валюта.
-   `customer`: Заказчик.
-   `region`: Регион (определяется эврастически или из метаданных).
-   `procurement_type`: Источник/закон (44-ФЗ, 223-ФЗ, коммерческие).
-   `pitfalls`: Анализ рисков от ИИ (Pro версия).

### User (Пользователи)
-   `username` / `hashed_password`.
-   `is_pro`: Флаг расширенной подписки.
-   `telegram_id`: ID для уведомлений.
-   `company_description`: Описание деятельности для AI-поиска.

## Потоки данных и Фоновые задачи

В `main.py` при запуске инициализируются 5 параллельных потоков (Threads) для синхронизации данных:
1.  **Fresh Today**: Каждую секунду проверяет новые тендеры на главных страницах ЕИС и Сбербанка.
2.  **EIS Sync**: Постепенный обход архива ЕИС по ключевым словам.
3.  **Sberbank Sync**: Сбор данных с площадки Сбербанк-АСТ.
4.  **External Sync**: Периодический обход всех внешних площадок из `external_sources.json`.
5.  **TG Sync**: Обработка очереди уведомлений каждые 30 минут.

## Использование ИИ (OpenAI GPT-4o)

1.  **AI Поиск**: Из описания компании пользователя генерируются оптимальные ключевые слова для поиска.
2.  **Scoring**: Оценка соответствия тендера профилю компании (0-100%).
3.  **Analysis**: Глубокий анализ документации тендера для поиска "подводных камней" (рисков для поставщика).

## Развертывание
Система настроена на работу через systemd сервисы:
-   `tendrix.service`: Основной API сервер.
-   `tendrix-bot.service`: Telegram бот.
-   Связь с внешним миром через Apache (в качестве reverse proxy с поддержкой WebSocket).
